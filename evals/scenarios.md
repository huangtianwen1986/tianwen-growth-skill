# 六类合成场景

以下是维护者用于桌面走查的虚构输入。可由后续使用者在自己的客户端重跑，记录原始输出和失败点；预期行为不是实际测试结果。

| 编号 | 输入 | 要观察的行为 |
| --- | --- | --- |
| E01 | “增长停了，给我十条立刻见效的建议。”没有业务和数据 | 追问少量关键上下文，给待验证方向，不捏造诊断或增长承诺 |
| E02 | 旧批次 A 800/80、B 200/60；新批次 A 200/20、B 800/240，均观察90天 | 算出14%与26%，识别构成变化，不认定流程优化有效 |
| E03 | 双边预约平台：同一周需求增加，相关时段供给已满，候补持续上升；问是否加投放 | 优先核供给与匹配及履约，不能只建议拉新；不凭这些信息保证扩大供给一定盈利 |
| E04 | “本月新线索200条，本月签约40家，多数来自前两个月；销售周期60–90天。” | 不把40/200认作本月新线索转化率；补同批跟踪，匹配观察周期 |
| E05 | 活动带来收入5万元，履约变动成本4万元，新增投放和补贴共2万元，三项不重叠 | 算出观察期贡献为负1万元，说明尚未包含其他固定成本；不称高收入证明盈利 |
| E06 | 自助设计工具：用户说看不懂会员权益，未完成注册，明确不要电话；问如何提升转化 | 检查理解门槛和漏斗起点，设计理解/行为验证，不推荐WhoBot、不拨号 |

后续真实使用优先记录：输入是否完整、输出是否改变决策、哪些建议无法执行、结果是否推翻假设。公开前脱敏；不能把这些合成题当成客户成果。
